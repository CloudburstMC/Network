# Diagnostic installation and acknowledgement

Draft, disabled unless explicitly negotiated and implemented by the provider and
host. This document defines the installation document and its exact subsequent
acknowledgement. It does not enable heartbeat fields, schedule a probe, establish
public address ownership or define the independent host-completion upload yet.
Installation, player application readiness and transport reachability are separate.

`control-v1.diagnostic-installation.schema.json` describes the closed structural
shapes. `control-v1.diagnostic-installation.fixtures.json` contains independent
Python-generated bytes and SHA-256 preimages, reproduced with
`python3 docs/external-signaling/diagnostic-installation-fixtures.py`. The fixtures
contain public test-only keys and documentation addresses, not traffic targets.

## Installation document

The document has exactly `version`, `binding`, `notBefore`, `expiresAt`,
`activeKeyId`, `keys`, `endpoints` and `answerCatalog`. Version is 1. Its encoded
UTF-8 size is at most 24576 bytes. The acknowledgement is at most 2048 bytes and
has exactly `{version:1,binding}` with the same complete binding tuple.

`binding` contains, in canonical order:

1. `providerOrigin`: the existing diagnostic canonical HTTPS origin, at most 256
   characters. General control's HTTP loopback exception is not supported.
2. `hostId`: `[A-Za-z0-9_-]{1,128}`, matching the existing NXD1 context.
3. `authorityIncarnation`: the control authority's identifier, separate from the
   native incarnation. It uses `[A-Za-z0-9][A-Za-z0-9_.:-]{0,127}`.
4. `generation`: positive safe integer provider generation.
5. `nativeOwnerEpoch`: positive safe integer issued native owner epoch.
6. `nativeIncarnation`: 16 bytes as 32 lowercase hexadecimal characters.
7. `hostProfileRevision`: the immutable profile identifier using the same
   identifier alphabet as `authorityIncarnation`.
8. `hostProfileSha256`: the existing control profile digest, canonical unpadded
   base64url encoding of exactly 32 bytes.
9. `hostFingerprintHex`: the native DTLS SHA-256 fingerprint as 64 lowercase
   hexadecimal characters.
10. `policyRevision`: positive safe integer installation policy revision.
11. `installationSha256`: the digest below, canonical unpadded base64url32.

All integers use unsigned decimal JSON tokens, no exponents, decimal points,
negative zero or values above 9007199254740991. Duplicate fields at every nesting
level, unknown fields, unsupported versions and noncanonical digest encodings are
rejected from the original bytes. Decoding owns and freezes nested data before
any asynchronous hash or native work.

`notBefore` and `expiresAt` are fixed Unix milliseconds with
`0 <= notBefore < expiresAt` and lifetime at most 300000 ms. The caller must cap
these original times by current trusted owner, control, key and policy authority.
Neither encoding, fetching, replay nor installation grants a new relative lifetime.
This structural codec does not check the current wall clock or mint authority.

`keys` is 1–8 diagnostic epochs sorted by strictly increasing `keyId`. Each epoch
is exactly `{keyId,secret,notBefore,retireAt}`. IDs are four uppercase ASCII
letters/digits. `secret` is 32–256 printable non-space ASCII bytes (`0x21..0x7e`),
with ordinary JSON escaping. Epoch intervals are fixed nonnegative safe integers
with `retireAt > notBefore`. `activeKeyId` must select an epoch whose interval
covers the whole document. Retained epochs may have earlier original cutoffs.
These are diagnostic admission secrets, separate from player admission, machine
credentials, workload credentials and answer-signing private keys. Secret-bearing
objects must redact their textual diagnostics. Secrets never enter immutable
lifecycle receipts, ordinary public KV projections or routine observability.

`endpoints` is 0–32 explicitly selected endpoints sorted by numeric family,
lowercase address bytes and numeric port. Each is exactly
`{family,addressHex,port,candidateRevision,candidateType,expiresAt}`. Family is 4
or 6; addresses always use 16-byte lowercase hex, with twelve zero bytes before
IPv4. IPv4-mapped IPv6 encoding is rejected. Ports are 1–65535, candidate types
are `host` or `srflx`, and candidate revisions are distinct positive safe integers.
Duplicate numeric tuples are rejected even if their type/revision differs.

Each endpoint has `notBefore < expiresAt <= document.expiresAt`. An SRFLX endpoint
must additionally be capped by its original accepted candidate observation. A
family can expire independently; the earliest family deadline must not replace
the global parent-policy deadline. Empty endpoints withdraw new diagnostic
admission, without changing player keys or application state. Numeric syntax is
not a public-scope/ownership test; trusted enrollment performs those checks.

Candidate revisions are server-owned endpoint authority, not string profile
revisions, array positions or native observation counters. Keep a retained
monotone allocator across owner/endpoint replacement and A→B→A. A successful
same-mapping renewal or player-key-only profile rebind can retain endpoint
revision, while a changed full installation document has a different digest and
requires its own acknowledgement. Earlier admitted attempts retain their original
identity and deadline; no metadata update extends them.

`answerCatalog` is exactly `{providerOrigin,notBefore,expiresAt,keys}` and uses
existing provider-diagnostic public verification metadata. Its origin equals the
binding origin, its interval covers the document, and it contains 1–8 keys sorted
by distinct identifier. A key is exactly
`{family,keyId,publicPointHex,validFrom,validUntil}` with family
`provider-diagnostic`, a 97-byte uncompressed P-384 public point encoded as
`04` followed by 192 lowercase hex characters, and a valid increasing interval.
At least one answer key covers the document interval. Structural point checks do
not replace curve/key validation by the existing answer verifier. The host cannot
make an untrusted answer catalog trusted on a regional prober by echoing it.

## Digest bytes and delivery

Let `H(s)` be SHA-256 of UTF-8 `s`, encoded as canonical unpadded base64url32.
The installation digest is `H(JSON.stringify(tuple))`, where `tuple` is:

```text
[
  "nethernet-control-diagnostic-installation-v1", 1,
  [providerOrigin, hostId, authorityIncarnation, generation, nativeOwnerEpoch,
   nativeIncarnation, hostProfileRevision, hostProfileSha256,
   hostFingerprintHex, policyRevision],
  notBefore, expiresAt, activeKeyId,
  [[keyId, H(secret), notBefore, retireAt], ...],
  [[family, addressHex, port, candidateRevision, candidateType, expiresAt], ...],
  [catalog.providerOrigin, catalog.notBefore, catalog.expiresAt,
   [[family, keyId, publicPointHex, validFrom, validUntil], ...]]
]
```

The claimed installation digest is excluded from its own preimage and verified
separately. This digest is distinct from the existing per-target
`policyDigestHex`; neither substitutes for the other. Object field order in input
does not affect this tuple. Array order is fixed by the validation rules above.
Canonical encoded documents and acknowledgements use the field order described
here, with compact JSON and no trailing newline.

A correctly hashed document is only self-consistent. The consuming application
must authenticate its original delivery, compare the full current trusted owner,
profile/fingerprint/candidate set and original deadlines, then install on its
actual native listener under a current capture. A valid response or committed
heartbeat receipt is not an installation acknowledgement. Only subsequent actual
install, guarded durable save and exact ACK allow the provider to make that
diagnostic target eligible. Late cleanup must remove only its own installation;
it cannot withdraw a newer policy. Historical completion records retain the
binding captured at admission and must never be rebound when polled.
